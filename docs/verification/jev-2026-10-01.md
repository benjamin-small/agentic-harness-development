## Failure found in the published runtime

The checksum-verified v2026.1001.174037 tarball returned `INVALID_RESPONSE` on its
first live library request. The CLI request was skipped. One additional
diagnostic request showed that OpenRouter returned the resolved model revision
`typesafe/jev-1.13-20260917`, while the validator demanded the request alias
`typesafe/jev-1.13`. The answers and usage passed offline validation when only
that model field was substituted for diagnosis.

The [official OpenRouter response example](https://openrouter.ai/docs/api/api-reference/alphadecisions/submit-a-decisions-request)
also uses the dated revision. The fix accepts exactly the alias or that revision,
preserves the returned ID, and rejects unknown revisions and unrelated models.
A regression verifies alias requests with dated responses; existing malformed
answer, usage, and completeness checks remain active.

Consumers of the old runtime must install v2026.1001.190334 or later, update the
recorded runtime path and pin deliberately, and preserve scoped local expertise.
Updating only the skill text does not fix the parser. Old artifacts remain
unchanged.

## Reproduce and interpret

Inject `OPENROUTER_API_KEY` into the authorized process, then use
`JEV_LIVE_SMOKE=1 npm run jev:smoke` from source. For a checksum-verified installed
release, invoke the source runner with `--package-root /absolute/package/root`.
The runner makes at most two calls per invocation and stops before the CLI call
if the library check fails. Each invocation can incur charges.

This proves real authentication, transport, response parsing, and answer
consumption on one fixture. It does not benchmark decision quality, adversarial
robustness, live batches, long-term provider availability, or native Pi/MCP
integration. The earlier fresh-Codex test verifies discovery separately; this
live test was executed by the harness using the Jev skill, not by repeating the
whole isolated Codex installation.
