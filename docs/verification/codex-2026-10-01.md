## Findings and limits

The earlier exploratory run was paused mid-installation for an interactive shell
and later timed out. It is **not counted as passing evidence**. Its UI/maintenance
selection excluded Jev, explaining why a manual request could not find that
skill. Installing a runtime that bundles the Jev executable does not install the
Jev skill. The clean run explicitly requested the capability and asserted native
discovery instead of treating a sample input file as proof of installation.

The clean agent recovered independently from an unavailable Python helper by
using Node, a checksum command in the wrong working directory, and duplicate npm
configuration paths. Public main and the release-tagged bootstrap differed; the
tagged maturity guide returned 404. The agent used release-tagged runtime guidance
and disclosed its use of newer main-branch maturity documentation. These were
observed recoveries, not a claim that every shell command succeeded first try.

The released Jev memory index incorrectly said the runtime was unimplemented.
This was corrected in source after the run; the tested release still contains
that stale note. Live provider verification remains pending. This editorial
correction does not retroactively change the tested artifact.

Native UI subagent registration, enforced fresh-context specialist execution,
automatic lifecycle hooks for Codex, user/deployment installations, upgrades,
rollback, live Jev transport, and decision quality were not established here.
Codex's startup check is a cooperative `AGENTS.md` instruction. No browser was
available for rendered UI verification. Nothing was pushed or deployed by the
container, and no OpenRouter key was supplied.
