# v2026.1002.2233

Run update polling directly without inference, and persist every shared-client
Jev call so library and CLI execution can be inspected locally.

- Add `poietic-harness poll` and `pollVersion`, with optional five-minute caching,
  ETag revalidation, and a default 1.5-second deadline. Exit codes distinguish
  no newer release (0), update available (1), and unavailable or invalid (2).
- Persist Jev starts, attempts, and outcomes to
  `~/.local/state/poietic-harness/jev/calls.jsonl`. Records include generated call
  IDs, timestamps, durations, attempt counts, and reported token/cost usage;
  credentials and request contents are omitted.
- Emit Jev CLI activity on stderr. `--quiet` suppresses terminal activity only;
  persistent logging remains enabled. JSON results stay on stdout.
- Document GitHub network access from the actual startup or scheduler context,
  and make deadline and batch concurrency tests independent of log-write latency
  on macOS runners.

and [bootstrap guide](https://github.com/benjamin-small/agentic-harness-development/blob/v2026.1002.2233/BOOTSTRAP.md).

Upgrade the runtime and exact consumer pin together, then refresh selected
instruction copies while preserving local expertise. Provision a writable log
path; use `JEV_LOG_PATH` or client `logPath` for an absolute override. Failed
persistence returns non-retryable `IO_ERROR`. A failure after dispatch may occur
after billing; do not automatically replay that request. Schedulers should check
`poll` availability fields independently of pin alignment. Existing `check`
behavior is preserved, and no scheduler or network permissions are installed.

Validation covers 69 automated tests, macOS and Linux on Node.js 24 and 26,
and isolated verification of the exact release package. No new paid inference
was invoked. The toolkit remains Alpha; broader decision quality, automatic
installation, and native specialist adapters remain unverified or planned.
