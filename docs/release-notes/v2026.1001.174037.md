# v2026.1001.174037

Poietic Harness can now check its installed version at session start and guide an
explicit scoped upgrade through the `poietic-harness:update` skill. Version pins
stay authoritative; startup checks never install or update automatically.

- Add the `poietic-harness` CLI and `/maintenance` TypeScript library, with local
  pin comparison, optional bounded GitHub lookup, JSON results, and offline use.
- Bundle a Claude Code maintenance plugin for `/poietic-harness:update` and
  SessionStart checks. Launch with `claude --plugin-dir <package>/dist/claude-plugin/poietic-harness`;
  portable startup guidance is documented for other harnesses.
- Add progressively loaded update knowledge and memory, including preservation
  of scoped private expertise, verified release acquisition, and rollback.
- Publish the significant-change changelog policy for human and harness readers.

See the [canonical changelog](https://github.com/benjamin-small/agentic-harness-development/blob/v2026.1001.174037/CHANGELOG.md#20261001174037--2026-10-01-174037-utc)
and this tag's [bootstrap guide](https://github.com/benjamin-small/agentic-harness-development/blob/v2026.1001.174037/BOOTSTRAP.md).
Existing consumers must install the new runtime and configure either the plugin
or portable startup guidance to enable the checks. The two-field version pin is
separate from a future capability/install lock.

Validation includes 52 automated tests, exact installed-consumer verification,
Claude Code 2.1.281 plugin manifest validation, and direct execution of the
packaged hook command. Interactive Claude discovery, a real user upgrade, and
live Jev inference remain unverified. Version alignment checks metadata, not
manually copied instruction content or a dirty source tree. Automatic installation,
UI detection, native subagent registration, and persistent services remain planned.
